MMV mapping system

Motor insurance

40% less manual mapping

Problem
Insurers describe the same vehicle in inconsistent Make, Model and Variant formats, so matching records across insurers took manual work.
What I built
A LangGraph service that finds candidate vehicles with hybrid BM25 and semantic search over OpenSearch, then has an LLM pick the match from verified records.
Result
An estimated 40% less manual mapping effort. Repeat queries are served from a Redis cache, which lowers latency and token cost.
  1. Insurer record
  2. BM25 + semantic search
  3. LLM match over candidates
  4. Redis cache
Engineering details
  • Hybrid retrieval combines BM25 keyword search with semantic vector search over an OpenSearch vector database, so the LLM picks from accurate candidates.
  • LangSmith tracks outputs and token usage. A fast, cost-efficient model and compacted prompts cut context size without losing match accuracy.
  • Strict and relaxed match thresholds are configurable.

  • RAG

Fraud and collusion detection

Insurance claims

30% fewer false-positive reviews

Problem
Collusion between claimants, garages and repair shops is hard to see when claims are reviewed one at a time.
What I built
A Neo4j knowledge graph of claims, claimants, garages and repair entities, with WCC and Leiden community detection plus fraud signals layered on top.
Result
Collusion networks surfaced across 10K+ synthetic claim records, with an estimated 30% fewer false-positive manual reviews.
  1. Claims knowledge graph
  2. WCC + Leiden communities
  3. Multi-signal fraud checks
  4. Agent explanation
Engineering details
  • Community detection runs in Neo4j Graph Data Science.
  • Fraud signals include narrative-to-damage mismatches, overcharged parts and invoice inconsistencies.
  • LangGraph agents run the pipeline end to end and write natural-language explanations, so non-technical reviewers can read why a claim was flagged.

SunDesk Copilot

An agentic RAG support assistant that corrects itself. A stateful LangGraph workflow routes each query, retrieves from Pinecone, has the LLM grade the evidence, and falls back to web search or a rewritten query when the evidence is weak.

  • Generates only from graded evidence, with source citations. Thin evidence returns an explicit "insufficient evidence" response.
  • Multi-turn memory with per-thread SQLite checkpointing and history-aware query rewriting.
  • Pydantic structured outputs for routing and grading, LangSmith tracing, and a SQLite audit log.
  • Ingests PDF, DOCX and Markdown. Ships as a FastAPI REST API and a Streamlit chat UI.
